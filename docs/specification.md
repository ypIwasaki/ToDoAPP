## 2. 目的

本アプリは、個人が日常のタスクを端末内で管理するためのAndroid用ToDoアプリである。タスクの登録、サブタスクへの細分化、期限と通知の設定、一覧およびカレンダーによる確認を提供する。

本アプリは個人利用を前提とし、ユーザー登録、外部アカウント連携、クラウド同期およびネットワーク通信を必要としない。

## 3. 対象範囲

### 3.1 対象機能

- タスクの登録、編集、削除、完了状態の管理
- タスクに対するメモの登録
- サブタスクの登録、編集、削除、完了状態の管理
- タスク期限の日付および時刻の設定
- タスク期限に基づくローカル通知
- タスク一覧の表示および状態による絞り込み
- 月間カレンダーによる期限付きタスクの確認
- ライトテーマおよびダークテーマへの対応
- 端末再起動、アプリ更新、日時・タイムゾーン変更、正確なアラーム権限再許可後の通知再登録

### 3.2 対象外機能

- ユーザー登録およびログイン
- クラウド同期、バックアップ、端末間転送
- タスクの共有および共同編集
- 外部カレンダーとの連携
- 繰り返しタスク
- タグ、カテゴリ、優先度
- タスクの検索
- データのインポートおよびエクスポート
- Web版およびiOS版

## 4. システム構成

### 4.1 アーキテクチャ

本アプリは、軽量なMVVMアーキテクチャにRepositoryパターンと単方向データフローを組み合わせる。

| レイヤー | 主な責務 | 主な実装 |
|---|---|---|
| View | 状態の表示、ユーザー操作の受付 | Jetpack Compose各画面 |
| ViewModel | 画面状態、画面遷移、入力値、UIイベントの管理 | `TodoViewModel` |
| Repository | データ操作と通知予約の調停 | `TaskRepository` |
| Data | タスクおよびサブタスクの永続化 | Room、`TaskDao` |
| Notification | 通知予約、永続バックアップ、重複防止、システムイベント後の再登録 | `ReminderScheduler`、各Receiver |

データ更新の基本的な流れは次のとおりとする。

```text
ユーザー操作
  → Compose View
  → TodoViewModel
  → TaskRepository
  → Room / AlarmManager・WorkManager
  → Flow / StateFlow
  → Compose Viewの再描画
```

## 5. 画面構成

### 5.1 共通ナビゲーション

メイン画面下部にナビゲーションバーを表示する。

| 項目 | 動作 |
|---|---|
| タスク | タスク一覧画面を表示する |
| カレンダー | カレンダー画面を表示する |
| フローティングアクションボタン | タスク登録画面を表示する |

タスク登録・編集画面では、画面上部の戻る操作またはAndroidの戻る操作によりメイン画面へ戻る。保存前の編集内容は破棄する。

### 5.2 タスク一覧画面

#### 5.2.1 表示内容

- 初期表示では「未完了」フィルターを選択する。
- 「すべて」「未完了」「完了」のフィルターチップを表示する。
- タスクカードには次の情報を表示する。
  - 完了チェックボックス
  - タスク名
  - メモ（入力されている場合、最大2行）
  - 期限（設定されている場合）
  - 期限切れ表示
  - サブタスクの完了数と総数
  - サブタスク進捗バー
  - 削除ボタン
- タスクカードを選択すると編集画面を表示する。
- サブタスク件数部分を選択すると、カード内のサブタスク一覧を開閉する。
- 展開されたサブタスクは一覧画面から直接完了状態を変更できる。

#### 5.2.2 並び順

タスクは次の優先順位で並べる。

1. 未完了タスク
2. 完了タスク
3. 期限ありのタスク
4. 期限が早いタスク
5. 作成日時が新しいタスク

#### 5.2.3 空状態

- 対象タスクが存在しない場合、空状態メッセージを表示する。
- 未完了またはすべての表示では、追加ボタンからタスクを登録するよう案内する。
- 完了表示では、タスクを完了すると表示されることを案内する。

### 5.3 タスク登録・編集画面

#### 5.3.1 入力項目

| 項目 | 必須 | 初期値 | 制約・動作 |
|---|---:|---|---|
| タスク名 | 必須 | 空 | 空白のみでは保存不可。保存時に前後の空白を除去する |
| メモ | 任意 | 空 | 複数行入力可。保存時に前後の空白を除去する |
| 期限の有無 | 任意 | 有効 | 無効時は期限と通知設定を保存しない |
| 期限日 | 期限有効時 | 翌日 | 日付選択ダイアログで変更する |
| 期限時刻 | 期限有効時 | 09:00 | 24時間表記の時刻選択ダイアログで変更する |
| 通知タイミング | 期限有効時 | 1時間前 | 規定の4候補から選択する |
| サブタスク | 任意 | なし | 任意件数を登録可能。空白の項目は保存時に除外する |

#### 5.3.2 保存処理

- タスク名が空の場合、エラーを表示して保存しない。
- 新規登録の場合、新しいタスクIDを採番する。
- 編集の場合、既存タスクを更新する。
- サブタスクは画面上の順番を`position`として保存する。
- 保存成功後はメイン画面へ戻り、完了メッセージを表示する。
- 保存処理中は戻る操作および保存操作を無効にする。

#### 5.3.3 期限に関する表示

- 過去の期限を指定した場合は警告を表示する。
- 過去の期限を持つタスクは保存できるが、通知は予約しない。
- 通知時刻がすでに過ぎ、期限自体は未来の場合は、保存後すみやかに通知を予約する。

### 5.4 カレンダー画面

#### 5.4.1 月間表示

- 月曜日始まりの月間カレンダーを6週間、42セルで表示する。
- 初期表示月と初期選択日は現在日とする。
- 前月、翌月および今日への移動操作を提供する。
- 現在日を枠線で示す。
- 選択日を背景色で示す。
- 期限付きタスクが存在する日には件数を表示する。
- 10件以上の場合は`9+`と表示する。

#### 5.4.2 日別タスク表示

- カレンダーで選択した日付を年月日および曜日付きで表示する。
- 選択日に期限が設定されているタスクを表示する。
- タスク名、期限時刻、完了状態、サブタスク進捗を表示する。
- チェックボックスからタスクの完了状態を変更できる。
- タスクを選択すると編集画面を表示する。
- 対象タスクがない場合は空状態を表示する。

## 6. 機能仕様

### 6.1 タスク管理

| 機能ID | 機能 | 仕様 |
|---|---|---|
| TASK-001 | タスク登録 | タスク名、メモ、期限、通知、サブタスクを登録する |
| TASK-002 | タスク編集 | 保存済みタスクの各項目を更新する |
| TASK-003 | タスク完了 | 一覧またはカレンダーから完了状態を切り替える |
| TASK-004 | タスク削除 | 確認ダイアログを表示した後、タスクを削除する |
| TASK-005 | タスク絞り込み | すべて、未完了、完了で一覧を絞り込む |
| TASK-006 | 期限切れ表示 | 未完了かつ期限を過ぎたタスクを期限切れとして表示する |

- タスクを完了しても、サブタスクの完了状態は自動変更しない。
- タスクを未完了へ戻した場合、将来の期限と通知設定があれば通知を再予約する。
- タスク削除時は関連するサブタスクと通知予約も削除する。
- 削除の取り消し機能は提供しない。

### 6.2 サブタスク管理

| 機能ID | 機能 | 仕様 |
|---|---|---|
| SUB-001 | サブタスク追加 | 編集画面から入力欄を追加する |
| SUB-002 | サブタスク編集 | 名称と完了状態を変更する |
| SUB-003 | サブタスク削除 | 編集画面から対象項目を削除する |
| SUB-004 | クイック完了 | 展開したタスクカードから完了状態を変更する |
| SUB-005 | 進捗表示 | 完了数／総数および進捗バーを表示する |

### 6.3 通知

#### 6.3.1 通知タイミング

| 選択肢 | オフセット値 |
|---|---:|
| 期限時 | 0分 |
| 10分前 | 10分 |
| 1時間前 | 60分 |
| 1日前 | 1,440分 |

通知予定時刻は「期限のUnix時刻（ミリ秒）－オフセット時間」で計算する。

#### 6.3.2 予約条件

次の条件をすべて満たす場合に通知を予約する。

- タスクが未完了である。
- 期限が設定されている。
- 通知タイミングが設定されている。
- 期限自体が未来である。

タスクの保存時は、同じタスクに対する以前の通知予約を解除してから新しい内容で予約する。

#### 6.3.3 通知表示

- 通知チャンネル名は「期限のお知らせ」とする。
- 通知チャンネルIDは`task_deadline_alerts_v2`とし、重要度を高に設定する。
- 画面点灯中はヘッドアップ通知として表示する。
- ロック画面でタスク名と期限を公開表示する。
- 全画面通知が許可されている場合、スリープ中に画面を点灯して期限画面を表示する。
- 全画面通知が未許可の場合、Androidの拡大ヘッドアップ通知へフォールバックする。
- 期限時のタイトルは「タスクの期限です」とする。
- 期限前のタイトルは「期限が近づいています」とする。
- 本文にはタスク名と期限日時を表示する。
- 通知を選択するとアプリのメイン画面を開く。
- 通知権限が許可されていない場合は通知を表示しない。
- 通知受信時にDBの最新状態を確認し、完了済みまたは期限・通知設定が変更済みの場合は古い通知を表示しない。
- AlarmManagerとWorkManagerの両方が起動した場合も、同じタスク・期限・通知タイミングの通知は一度だけ表示する。

#### 6.3.4 再登録

次のシステムイベント受信後、未完了かつ期限付きのタスクについて通知を再登録する。

- 端末起動完了（`BOOT_COMPLETED`）
- アプリ更新完了（`MY_PACKAGE_REPLACED`）
- システム日時変更（`TIME_SET`）
- タイムゾーン変更（`TIMEZONE_CHANGED`）
- 正確なアラーム権限の再許可（`SCHEDULE_EXACT_ALARM_PERMISSION_STATE_CHANGED`）
- アプリがフォアグラウンドへ戻った時

#### 6.3.5 精度

`SCHEDULE_EXACT_ALARM`が許可されている場合は`AlarmManager.setExactAndAllowWhileIdle`を使用し、アプリプロセスが存在しない状態およびDoze中も期限時刻どおりに起動する。未許可の場合は`setAndAllowWhileIdle`へフォールバックするため、通知時刻が前後する場合がある。
| `USE_FULL_SCREEN_INTENT` | スリープ中の画面点灯と期限画面表示 |

AlarmManagerとは別にWorkManagerへ同じ通知を一意なWorkとして登録し、予約消失時のバックアップとする。

## 7. データ仕様

### 7.1 データベース

| 項目 | 内容 |
|---|---|
| DB名 | `todo.db` |
| DB方式 | Room / SQLite |
| スキーマバージョン | 1 |
| スキーマ出力 | 有効 |

### 7.2 tasksテーブル

| カラム | 型 | NULL | 説明 |
|---|---|---:|---|
| id | Long | 不可 | 主キー、自動採番 |
| title | String | 不可 | タスク名 |
| description | String | 不可 | メモ。未入力時は空文字 |
| deadlineEpochMillis | Long | 可 | 期限のUnix時刻（ミリ秒） |
| reminderOffsetMinutes | Int | 可 | 期限から通知までの分数 |
| isCompleted | Boolean | 不可 | 完了状態 |
| createdAt | Long | 不可 | 作成日時のUnix時刻（ミリ秒） |
| updatedAt | Long | 不可 | 更新日時のUnix時刻（ミリ秒） |

### 7.3 subtasksテーブル

| カラム | 型 | NULL | 説明 |
|---|---|---:|---|
| id | Long | 不可 | 主キー、自動採番 |
| taskId | Long | 不可 | 親タスクID |
| title | String | 不可 | サブタスク名 |
| isCompleted | Boolean | 不可 | 完了状態 |
| position | Int | 不可 | 表示順 |
| createdAt | Long | 不可 | 作成日時のUnix時刻（ミリ秒） |

### 7.4 リレーション

- 1つのタスクは0件以上のサブタスクを持つ。
- `subtasks.taskId`は`tasks.id`を参照する外部キーとする。
- 親タスク削除時は関連するサブタスクをCASCADE削除する。
- `subtasks.taskId`にインデックスを設定する。

### 7.5 日時とタイムゾーン

- 日時はUnix時刻のミリ秒値でDBへ保存する。
- 入力および表示は端末のシステムタイムゾーンを使用する。
- 日付表示は日本語ロケールを使用する。
- 時刻は24時間表記とする。

## 8. 権限・プライバシー仕様

### 8.1 使用権限

| 権限 | 用途 |
|---|---|
| `POST_NOTIFICATIONS` | タスク期限通知の表示 |
| `RECEIVE_BOOT_COMPLETED` | 再起動後の通知再登録 |
| `SCHEDULE_EXACT_ALARM` | Doze中およびアプリ終了中の正確な期限通知 |
| `USE_FULL_SCREEN_INTENT` | スリープ中の画面点灯と期限画面表示 |

- 初回起動時に通知権限を要求する。
- 通知権限を拒否した場合も、通知以外のタスク管理機能は利用可能とする。
- `INTERNET`権限は使用しない。
- 正確なアラーム権限が未許可の場合、タスク一覧に設定への案内を表示する。
- 全画面通知が未許可の場合、タスク一覧に設定への案内を表示する。
- 通知チャンネルの重要度が「高」未満の場合、ポップアップ通知設定への案内を表示する。
- 通知権限が無効、またはバックグラウンド実行が「制限付き」の場合も案内を表示する。

### 8.2 データ保護

- すべてのユーザーデータをアプリのローカルDBに保存する。
- 外部サーバーへのデータ送信を行わない。
- Androidのクラウドバックアップを無効にする。
- Androidの端末間データ転送からアプリデータを除外する。
- アプリをアンインストールすると保存データも削除される。

## 9. テーマ・ユーザビリティ仕様

- Material Design 3を使用する。
- 端末のシステム設定に応じてライトテーマとダークテーマを切り替える。
- 主要なアイコンボタンにアクセシビリティ用の内容説明を設定する。
- タスクおよびサブタスクの完了状態はチェックボックスと取り消し線で示す。
- 期限切れ状態はエラーカラーで示す。
- 保存、削除などの結果をSnackbarで通知する。

## 10. 非機能要件

### 10.1 対応環境

- Android 16（API 36）以降の実機またはエミュレーターで動作すること。
- 画面のライト／ダーク設定変更後も表示が維持されること。
- 端末のローカルタイムゾーンで期限を表示すること。

### 10.2 信頼性

- DB操作をメインスレッドで実行しないこと。
- RoomのFlowを利用し、DB変更を一覧とカレンダーへ反映すること。
- タスクの更新、完了、削除に伴う古い通知を表示しないこと。
- 端末再起動後に有効な通知を再登録すること。
- アプリ更新、日時・タイムゾーン変更、正確なアラーム権限再許可後に有効な通知を再登録すること。
- 通知予約をAlarmManagerとWorkManagerで冗長化し、同一通知の二重表示を防ぐこと。

### 10.3 保守性

- View、ViewModel、Repository、Data、Notificationの責務を分離すること。
- UIからRoomおよびAlarmManagerを直接操作しないこと。
- 日付配置および通知時刻計算を単体テスト可能な純粋関数として保持すること。
- DBスキーマ変更時はRoom MigrationとDBバージョン更新を追加すること。

## 11. エラー・例外時の動作

| 条件 | 動作 |
|---|---|
| タスク名が未入力 | 入力エラーを表示し、保存しない |
| 編集対象タスクが存在しない | メイン画面へ戻り、エラーメッセージを表示する |
| 通知権限が拒否されている | 通知を表示せず、アプリの他機能は継続する |
| 正確なアラーム権限が未許可 | 設定への案内を表示し、非正確アラームとWorkManagerへフォールバックする |
| バックグラウンド実行が制限付き | Androidのアプリ設定への案内を表示する |
| 期限が過去 | タスクは保存するが通知を予約しない |
| サブタスク名が空白 | そのサブタスクを保存対象から除外する |
| タスク削除 | 確認後にタスク、サブタスク、通知予約を削除する |

## 12. 受入条件

| ID | 確認内容 | 期待結果 |
|---|---|---|
| AC-001 | タスク名を入力して保存する | 未完了一覧にタスクが表示される |
| AC-002 | タスク名を空にして保存する | エラーが表示され、保存されない |
| AC-003 | 複数のサブタスクを登録する | 編集画面と一覧展開時に登録順で表示される |
| AC-004 | タスクを完了する | 未完了一覧から消え、完了一覧に表示される |
| AC-005 | 完了したタスクを未完了に戻す | 未完了一覧に再表示される |
| AC-006 | タスクを削除する | タスクと関連サブタスクが一覧から消える |
| AC-007 | 期限を設定する | 一覧とカレンダーの該当日に表示される |
| AC-008 | カレンダーの日付を選択する | その日に期限を持つタスクだけが表示される |
| AC-009 | 通知権限を許可して未来の通知を設定する | 設定したタイミング付近で通知される |
| AC-010 | 通知予約後にタスクを完了または削除する | 以前の通知が表示されない |
| AC-011 | 端末を再起動する | 有効な未完了タスクの通知が再登録される |
| AC-012 | システムテーマを変更する | アプリのライト／ダークテーマが追従する |
| AC-013 | 通知権限を拒否する | 通知以外の機能が利用できる |
| AC-014 | Android 15以前へインストールする | 非対応OSとしてインストールされない |
| AC-015 | アプリを終了して通知時刻を待つ | アプリを手動起動しなくても通知される |
| AC-016 | 通知予約後に日時またはタイムゾーンを変更する | 有効な通知が再登録される |
| AC-017 | 正確なアラーム権限を再許可する | 有効な通知が正確なアラームとして再登録される |
| AC-018 | AlarmManagerとWorkManagerが同一通知を処理する | 通知は一度だけ表示される |
| AC-019 | 画面点灯中に通知時刻を迎える | 画面上部にヘッドアップ通知が表示される |
| AC-020 | スリープ中に通知時刻を迎える | 画面が点灯し、ロック画面上に期限内容が表示される |

## 14. 既知の制約

- ユーザーがAndroidの「強制停止」を実行した後は、OSの停止状態が解除されるまで通知できない。アプリを手動起動すると保存済みタスクから再登録する。
- 正確なアラーム権限が未許可の場合、フォールバック通知は端末状態によって遅延する場合がある。
- バッテリー設定が「制限付き」の間は、アラーム、Jobおよび起動完了通知が抑止される場合がある。
- 全画面通知とロック画面通知の最終的な表示可否は、ユーザーのAndroid通知設定が優先される。
- 通知から特定タスクの編集画面へ直接遷移せず、メイン画面を表示する。
- 編集途中の入力内容はアプリプロセス終了後に復元しない。
- タスク削除後の復元機能はない。
- ユーザーによる並べ替えには対応しない。
- DBスキーマは初版であり、過去バージョンからのMigrationはまだ存在しない。
- デバッグAPKは開発用署名であり、一般配布にはリリース用署名が必要である。
